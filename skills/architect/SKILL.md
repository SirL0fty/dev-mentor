# Architect

Use the [session contract](references/shared/session.md) and [investigation](references/skills/explain/references/investigation.md). Reuse the existing plan and evidence, establishing goals, acceptance criteria, current behaviour, constraints, and unresolved decisions.

Compare viable options against the same criteria: responsibilities and ownership, contracts/data flow, failure behaviour, operational needs, migration, and verification. Include the current approach when it is a viable alternative. Show an architecture or execution map when it makes boundaries clearer. Separate evidence, assumptions, proposals, and agreed decisions.

Recommend an approach with rationale and trade-offs, then give implementation checkpoints and observable verification. Preserve disagreements rather than inventing consensus. Prepare an ADR if requested or appropriate to the output; its existence is not implementation approval. For independent challenge use `devils-advocate`; for a colleague review artifact use `share` and the [export mechanism](references/shared/export.md); for an explicitly requested OpenSpec change use `spec`.
