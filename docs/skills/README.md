# Skill guides

One page per skill: what it does, when to reach for it, and what you should see when it's working. The **It's working if** lists double as checks: before changing a skill, try the relevant ones in a fresh session.

Lessons that change code (`coach`, `spec`) start with the project preflight; its checks are in the [mentor-style](mentor-style.md) guide. `architect` and `devils-advocate` first ask for diagrams or docs the repo can't show and confirm how the system works, so every reviewer shares the same context. Design questions then get the smallest proposed design that fits, in `architect`, `devils-advocate` and `share`'s ADR; see their guides.
