# Skill guides

One page per skill: what it does, when to reach for it, and what you should see when it's working. The **It's working if** lists double as checks: before changing a skill, try the relevant ones in a fresh session.

Lessons that change code (`coach`, `spec`) start with the project preflight; its checks are in the [mentor-style](mentor-style.md) guide. `architect` and `devils-advocate` first ask for diagrams or docs the repo can't show and confirm how the system works, so every reviewer shares the same context. Design questions then get the simplest proposed design that fits, starting from what already exists, in `architect`, `devils-advocate` and `share`'s ADR; see their guides. `share` sends as an HTML file (password optional), the Markdown file, or a connected tool. Every skill shows real evidence (commands, output, code) explained for your level, and asks whether you or the AI runs tests and commands; see the [mentor-style](mentor-style.md) guide.
